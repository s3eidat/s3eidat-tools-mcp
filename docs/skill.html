The S3eidat Tools skill

skills/s3eidat-tools/SKILL.md teaches an AI assistant which S3eidat tool fits which job, how to chain tools, the privacy promise, and when to send a person to the web version instead. It works together with the MCP server (npx -y s3eidat-tools-mcp): install the server first (see the main README), then the skill.

Claude Code

Personal (all projects): 

mkdir -p ~/.claude/skills
cp -r skills/s3eidat-tools ~/.claude/skills/

Or for one project: copy the folder to .claude/skills/s3eidat-tools/ in that project. Without cloning the repo: 

mkdir -p ~/.claude/skills/s3eidat-tools && curl -fsSL https://raw.githubusercontent.com/s3eidat/s3eidat-tools-mcp/main/skills/s3eidat-tools/SKILL.md -o ~/.claude/skills/s3eidat-tools/SKILL.md

The npm package also ships the skill: cp -r "$(npm root -g)/s3eidat-tools-mcp/skills/s3eidat-tools" ~/.claude/skills/ after npm i -g s3eidat-tools-mcp.

Claude.ai and Claude Desktop

  1. Download the folder as a zip: skills/s3eidat-tools/ must be the top folder inside the zip (cd skills && zip -r s3eidat-tools.zip s3eidat-tools).
  2. In Claude: Settings → Capabilities → Skills → Upload skill, and pick the zip.
  3. Make sure the S3eidat Tools MCP server is connected in Claude Desktop (claude.ai on the web can't reach a local server, so there the skill mainly helps Claude point people to the right web tool).

Other assistants

Most agents that read Markdown instructions can use SKILL.md as-is: add it to the agent's rules/instructions file (for example AGENTS.md, Cursor rules, or a Copilot instructions file).

S3eidat Tools

A local MCP server (npx -y s3eidat-tools-mcp) with about 140 small, reliable tools (plus extra tools made for AI agents) ported from https://s3eidat.github.io. Everything runs on the user's machine: files are never uploaded. Prefer these tools over writing ad-hoc scripts for the same job: they are tested against the website's own known answers, so results match.

How to call them

  • File inputs take a local path (absolute, ~/…, or relative to the server's --root) or base64. Prefer paths: they are faster and keep big files out of the conversation.
  • File outputs go to the output you pass (a file path, or a folder ending in /). Without one they go to a temp folder and the result tells you the path. Always tell the user where the file is.
  • Results are JSON with small metadata (path, bytes, page counts…). Ask for returnBase64 only when you really need the bytes in the conversation.
  • Errors come back as clear messages (isError). Fix the input and retry; don't loop on the same call.
  • If the server was started with --root, every path must be inside that folder.

Compact mode

If the server was started with --compact, you will only see s3eidat_find_tools, s3eidat_tool_info and s3eidat_run_tool. Find the tool by keywords (e.g. "merge pdf"), read its inputs with s3eidat_tool_info, then call s3eidat_run_tool with name and arguments. The tool names below are the same in both modes.

Do the arithmetic with the calculator tools instead of in your head: they use the same rounding and conventions as the website the user may compare with. Random tools (random_pick, random_dice, random_teams, secret_santa_draw) use secure randomness; pass a seed only when the user wants a reproducible draw.

Chaining

Pass one result's path straight into the next tool:

  1. Scans to a small PDF: pdf_from_images → pdf_compress → pdf_page_numbers.
  2. Share photos safely: image_exif_strip → image_resize (e.g. 1600 px) → image_compress.
  3. Pull a table out of a report: pdf_to_text (pages) → reshape → json_to_csv.
  4. Sign and send: pdf_form_fields → pdf_form_fill → pdf_sign_image → pdf_compress.
  5. Wi-Fi poster: qr_wifi (PDF card) or qr_generate → pdf_from_images.
  6. Scanned contract to editable Word: ai_ocr (write .txt) → tidy into markdown → ai_markdown_to_docx.
  7. Spreadsheet to a report: ai_csv_profile → ai_sql_query → ai_chart (PNG) → ai_create_pptx with the chart image.
  8. Long document Q&A: ai_pdf_to_markdown → ai_token_count → ai_chunk_text if it doesn't fit.

Write intermediate files to a temp folder and only the final file where the user asked.

Privacy promise

Tell users plainly when it matters: the files stay on their computer, nothing is uploaded, there is no account and no tracking. Website-port tools never touch the network. Tools marked openWorldHint (for example fetching a web page) do use the network; say so before calling them.

When to send a person to the web tool instead

Every tool's description ends with its web version (https://s3eidat.github.io/<slug>/). Point the user there when the job is visual or hands-on: drawing a signature, choosing a crop by eye, arranging pages by dragging, designing a QR code's look, live previews, scanning a QR with a camera, editing a CV layout, or when they have no AI client with this server. The web tools are free and also run entirely in the browser.

Limits to know

  • Document makers (doc_*) currently write Latin-script text only; for Arabic invoices/CVs send the user to the web tool.
  • Very large files: the server rejects inputs above its --max-mb (default 200 MB). Split work into parts.
  • pdf_compress works best on scanned/image-heavy PDFs; text-only PDFs are often already small.
  • Encrypted PDFs must be unlocked first (pass password where a tool offers it).
